# E3: human-robot safety scenarios (2D simulator)

```
uv run python scripts/e3_one_scene.py SCENE_DIR --name P18 --seeds 10      # one scene: variants, 3 tiers x seeds x 3 policies
```

Code: `src/worldc/e3/` (outside the E1 freeze). `world.py` turns a built scene into 2D grids and task points, `walkers.py`
draws the seeded workers, `sim.py` runs the robot under a policy and measures, and `tiers.py` builds the tier variants.
No Isaac Sim is needed. Isaac replay of a subset is not built yet.

## Scenes and tiers

Every scene is rebuilt from its `resolved_spec.json` with the LLM-authored agents removed, because E3's walkers replace them.

| tier | variant | workers |
|---|---|---|
| easy | `base` | 1 |
| medium | `base` | 3 |
| hard | `hard` = `base` + 2-4 `parts_shelf` units (0.92 x 0.61 x 2.44 m) beside walkways | 6 |

How the hard variant is built:
- **Seed:** the transform seed (default 0) draws the number of units and the order in which candidates are tried. It is
  separate from the trial seeds, so the hard geometry is fixed per scene.
- **Placement:** candidates stand beside the walking paths, axis-aligned, with a 1.2 m aisle kept.
- **Acceptance:** a unit is kept when the set passes a 2D pre-check (every task point reachable from the door through
  1.2 m aisles, every robot goal reachable) and the solver places it.
- **Final check:** the rebuilt scene must pass `check_scene` (static only, no physics).

Each variant's `e3_variant.json` records the transform and the check result.

## Trials

- **Seed:** a trial seed fixes every worker. Worker `i` draws from `default_rng([seed, i])`, so the same seed gives the
  same people in every policy. A walking path is always planned in one canonical direction, so it does not depend on
  which paths were asked for first. Worker `i` is also the same person in every tier, apart from paths that the hard tier's
  occluders change.
- **Task points:** door (exits), bench (stand points), storage (zone centres) and cell gate (outside the cell's
  `gate_*` collider), taken from the scene graph's `safety` block.
- **Tours:** 3-6 tasks per worker. Paths are A* on the grid inflated by 0.26 m, then smoothed.
- **Motion:** preferred speed 1.3 ± 0.2 m/s, 0.8 m/s² acceleration, slower at corners. Dwell at each task is lognormal
  (median 5 s). A uniform start offset puts workers at different points of their tours.
- **Walkers do not react** to the robot or to each other (stated limitation). Human-human overlap is reported.
- **Robot:**
  - **Body:** the footprint is the robot table's measured bounds (Nova Carter: 0.73 m along local x, 0.90 m along y).
  - **Travel direction:** the Isaac drive calibration of the base scene measured local +x
    (`travel_heading_in_robot_frame_rad` = 0.001).
  - **Motion:** unicycle with `isaac_drive`'s pure pursuit, 1.0 m/s, visiting every goal in scene order.
  - **Timeout:** 3 x (path length / speed + 6 s per goal) + 30 s.
- **Policies:**
  - *blind* ignores people.
  - *stop* halts while a person is within 1.0 m ahead and resumes after 1 s clear.
  - *aware* treats people as obstacles inflated by 0.5 m at 5 Hz, replans when the path ahead is blocked, and scales
    speed, linear and angular, from full at 2.0 m to zero at 0.5 m.
  - Both cautious policies apply their checks to the align turn at each goal: stop-and-wait holds the turn under its
    1.0 m rule, and human-aware scales its rotation. The align time limit (4 s) pauses while the robot holds.

## Metrics (per trial)

Gaps are measured from the robot's footprint rectangle to a person's disk; a gap of 0 is a collision.

**Moving vs stationary.** The robot is *moving* when |v| > 0.05 m/s or |ω| > 0.2 rad/s, so turning in place counts as
moving. Walkers do not react, so collisions are split:
- **Primary:** `collisions_robot_moving` (the robot's doing).
- Also reported: `collisions` (all) and `collisions_robot_stationary` (a person walked into the robot).

**Outcome:**
- `success`: every goal reached within the timeout and no robot-moving collision.
- Otherwise one of: `collision` (robot moving), `frozen` (no 0.1 m of progress in 30 s while driving, or holding an
  align turn for 30 s), `timeout`, `goal_unreachable` or `goal_missed`.

**Exposure and timing:**
- `min_gap_m` and `min_gap_moving_m`.
- `time_within_{0.5,1,2}m_s` and `time_within_{0.5,1}m_moving_s`.
- `time_to_goal_s` and `stationary_s`.
- `stationary_near_1m_s`: time the robot stands within 1.0 m of a person.

**Other:** `human_human_overlap_s`, `replans` and `hold_s`.

Per trial, `trials.jsonl` also keeps the drawn workers, every collision event, the robot trajectory and a digest. The
runner rebuilds one trial from its seed and checks that the digest matches.

## Analysis (`scripts/e3_analysis.py`)

```
uv run python scripts/e3_analysis.py out/e3/*/trials.csv --out results/e3_analysis
```

- **CIs:** 95 % percentile intervals from a two-stage cluster bootstrap (2000 replicates). Each replicate resamples
  scenes, then seeds within each drawn scene. The same draw is used for every tier and policy, so cells stay paired.
- **Tests:** per tier, a paired Wilcoxon signed-rank test for each policy pair on identical (scene, seed) trials, for
  robot-moving collisions and time to goal. An unfinished trial counts at its timeout. p-values are Holm-corrected
  within each metric.
- **Outputs:**
  - `table2.md` / `table2.tex`: one row per tier x policy. Moving collisions first, then all collisions, success,
    frozen, min gap while moving, time within 0.5 / 1 m while moving, time stationary within 1 m, and median time to
    goal.
  - `tests.md` / `tests.csv`.
  - `scatter.svg` and `scatter_points.csv`: moving collisions against median time to goal, one point per policy x
    tier, with CIs.

## Scene selection (`scripts/e3_select_scenes.py`)

```
uv run python scripts/e3_select_scenes.py dataset/e1/<model> --n 10 --out results/e3_scene_selection
```

- **Candidates:** accepted E1 runs with physics ok, usable for E3 (a door, at least two kinds of task point, at least
  two reachable robot goals).
- **Pick:** greedy, one scene per prompt. It covers every cell-type family (engine and motor gearbox reman count as one,
  which gives 6) and every size, then new (family, size) combinations, then balances families, difficulty and size.
- **Safe during E1:** it only reads records and loads 2D grids. The trial grid itself should not run on the E1 machine
  while E1 runs.
