# E3: human-robot safety scenarios (2D simulator)

```
uv run python scripts/e3_one_scene.py SCENE_DIR --name P18 --seeds 10      # one scene: variants, 3 tiers x seeds x 3 policies
uv run python scripts/e3_grid.py --variants-only                           # the selected scenes: variants + reachability report
uv run python scripts/e3_grid.py --seeds 30 --jobs 8                       # the full grid, resumable (out/e3/grid/<scene>/trials.jsonl)
```

Code: `src/worldc/e3/` (outside the E1 freeze). `world.py` turns a built scene into 2D grids and task points, `walkers.py`
draws the seeded workers, `sim.py` runs the robot under a policy and measures, and `tiers.py` builds the tier variants.
No Isaac Sim is needed. Isaac replay of a subset is not built yet.

## Scenes and tiers

Every scene is rebuilt from its `resolved_spec.json` with the LLM-authored agents removed, because E3's walkers replace them.

| tier | variant | workers |
|---|---|---|
| easy | `base` | 1 |
| medium | `base` | 3 |
| hard | `hard` = `base` + as many `parts_shelf` units (0.92 x 0.61 x 2.44 m) beside walkways as fit, 0-4 | 6 |

How the hard variant is built (rule fixed before the grid):
- **Count:** as many units as fit, 0 to 4. It is not drawn; the actual count is recorded per scene (`occluder_count`).
- **Order:** the transform seed (default 0) draws the order in which candidate poses beside the walking paths are tried. It is
  separate from the trial seeds, so the hard geometry is fixed per scene.
- **Placement:** candidates stand beside the walking paths, axis-aligned, with a 1.2 m aisle kept, at least 2.5 m apart.
- **Acceptance:** a unit is kept when (a) no task point leaves the door's 1.2 m aisle network that it was on without the units,
  (b) every robot goal stays reachable from the spawn, and (c) the solver places it. Stand points on the back of a bench (between
  it and a wall) are never on the network, so the test is relative to the scene without units, not absolute.
- **Final check:** the rebuilt scene must pass `check_scene` (static only, no physics); `variants_report.json` re-verifies goals
  and task points on the built hard scene and that six walker paths can be planned. A scene is redrawn only if six workers alone
  (no occluders) would make a goal unreachable.
- **Base rebuild:** from the scene's `resolved_spec.json`. Where stacked items make that unbuildable, from the run's `spec.json`
  with the agents removed; `e3_variant.json` records `spec_source` and the instances that moved against the E1 scene.

Each variant's `e3_variant.json` records the transform and the check result.

## Trials

- **Seed:** a trial seed fixes every worker. Worker `i` draws from `default_rng([seed, i])`, so the same seed gives the
  same people in every policy. A walking path is always planned in one canonical direction, so it does not depend on
  which paths were asked for first. Worker `i` is also the same person in every tier, apart from paths that the hard tier's
  occluders change.
- **Task points:** door (exits), bench (stand points), storage (zone centres) and cell gate (outside the cell's
  `gate_*` collider), taken from the scene graph's `safety` block.
- **Tours:** 3-6 tasks per worker. Paths are A* on the grid inflated by 0.26 m, then smoothed.
- **Motion:** preferred speed 1.3 ± 0.2 m/s, 0.8 m/s² acceleration, slower at corners. Dwell at each task is lognormal
  (median 5 s). A uniform start offset puts workers at different points of their tours.
- **Walkers do not react** to the robot or to each other (stated limitation). Human-human overlap is reported.
- **Robot:**
  - **Body:** the footprint is the robot table's measured bounds (Nova Carter: 0.73 m along local x, 0.90 m along y).
  - **Travel direction:** the Isaac drive calibration of the base scene measured local +x
    (`travel_heading_in_robot_frame_rad` = 0.001).
  - **Motion:** unicycle with `isaac_drive`'s pure pursuit, 1.0 m/s, visiting every goal in scene order.
  - **Timeout:** 3 x (path length / speed + 6 s per goal) + 30 s.
- **Policies:**
  - *blind* ignores people.
  - *fields* (ISO 3691-4-style stop-and-wait) has a protective field and a warning field. Both are rectangles ahead of
    the footprint's front edge along the travel heading, as wide as the footprint plus 0.25 m a side. While the robot
    turns (|ω| > 0.2 rad/s, the align turn included) they widen by another 0.15 m a side.
    - **Lengths, recomputed every step from the current speed (field switching):**
      - protective = v·T_react + v²/(2·a_brake) + 1.6 m/s·(T_react + v/a_brake) + margin. The third term is an
        ISO 13855-style human approach: a person closing in at 1.6 m/s while the robot reacts and brakes.
      - warning = protective + 1.0 m
    - **Protective:** a person's disk in the field stops the robot, braking at a_brake. It resumes once the field has
      been clear for 1 s.
    - **Warning:** a person in the field slows the robot, linear and angular, to 50 %, and the time is flagged
      (`field_warning_s`).
    - **Parameters:** all in `sim.FIELDS`. T_react is 0.1 s and the margin 0.25 m. a_brake comes from the robot table
      (`brake_decel_mps2`). For Nova Carter it is 1.5 m/s², a conservative assumption (half of `worldc drive`'s 3.0 m/s²
      deceleration limit), not a vendor spec. That gives 0.41 m standing still and 1.91 m at 1.0 m/s.
    - **Limits:** the fields look only ahead. A person overtaking from behind, or standing beside the robot while its
      corner sweeps through a turn in place, is not seen. The approach term lengthens the field ahead only, so a
      person crossing into its side close to the robot can still reach it while it brakes.
  - *aware* treats people as obstacles inflated by 0.5 m at 5 Hz, replans when the path ahead is blocked, and scales
    speed, linear and angular, from full at 2.0 m to zero at 0.5 m.
  - Both cautious policies apply their checks to the align turn at each goal: fields holds or slows the turn under its
    fields, and human-aware scales its rotation. The align time limit (4 s) pauses while the robot holds.

**Frozen policies (`e3-policies-v1`).** The definitions above are frozen at the git tag `e3-policies-v1`
(`sim.POLICIES_TAG`). Every trial row records:
- `e3_policies`, the tag name.
- `e3_policies_commit`, the commit the tag names.
- `code_commit`, the commit that ran the trial.
- `policies_at_tag`, true when `sim.py` and the robot table are unchanged since the tag. The runner warns otherwise.

A policy change needs a new tag. The remaining collision modes are reported as findings, not fixed:
- fields: people coming from behind (overtakes, turns in place), and people crossing into the side of the field while
  the robot brakes.
- human-aware: freezing in dense scenes.

## Metrics (per trial)

Gaps are measured from the robot's footprint rectangle to a person's disk; a gap of 0 is a collision.

**Moving vs stationary.** The robot is *moving* when |v| > 0.05 m/s or |ω| > 0.2 rad/s, so turning in place counts as
moving. Walkers do not react, so collisions are split:
- **Primary:** `collisions_robot_moving` (the robot's doing).
- Also reported: `collisions` (all) and `collisions_robot_stationary` (a person walked into the robot).
- `collisions_robot_moving_from_behind`: robot-moving collisions where the person's centre was behind the robot's centre
  along the travel heading. Each collision event carries `ahead_x`, `from_behind`, `robot_holding` (the policy
  was holding, i.e. braking or stopped) and `state`. `collisions_robot_moving_braking` counts the robot-moving ones
  where the robot was already braking.

**Why human-aware registers no moving collisions.** Its speed scale (linear and angular, the align turn included) is
`clip((g - 0.5) / (2.0 - 0.5), 0, 1)`, with g the gap from the footprint to the nearest person's disk, the same gap the collision
test uses (contact at g = 0). The target speed therefore reaches zero at g = 0.5 m, 0.5 m before contact, and the robot sheds speed
at 3 m/s^2 (8 rad/s^2 for turning). A walker (1.3 +/- 0.2 m/s) needs about 0.4 s to close 0.5 m, the robot about 0.1 s to stop
from the 0.33 m/s allowed at g = 1 m, so under this metric a human-aware contact can only be a person walking into a robot that has
already stopped. In the grid it is exactly that: all 3,715 human-aware collisions have the robot's logged |v| and |w| at 0.00
(the log rounds to 0.01) and are tagged stationary. The primary metric is therefore zero for this policy by construction and
says nothing about its safety: read it together with `collisions_robot_stationary` (people walking into the stopped robot,
which the policy does not prevent because walkers do not react), the frozen rate, success and time to goal. The robot's own speed
at contact is not the impact speed: for a stationary contact the relative speed is the walker's. A contact is counted once, at its
first step, with the robot's state at that step. The checks are in `results/e3_grid/analysis/contact_speed.md`.

**Outcome:**
- `success`: every goal reached within the timeout and no robot-moving collision.
- Otherwise one of: `collision` (robot moving), `frozen` (no 0.1 m of progress in 30 s while driving, or holding an
  align turn for 30 s), `timeout`, `goal_unreachable` or `goal_missed`.

**Exposure and timing:**
- `min_gap_m` and `min_gap_moving_m`.
- `time_within_{0.5,1,2}m_s` and `time_within_{0.5,1}m_moving_s`.
- `time_to_goal_s` and `stationary_s`.
- `stationary_near_1m_s`: time the robot stands within 1.0 m of a person.

**Other:** `human_human_overlap_s`, `replans`, `hold_s`, and for fields `protective_stops` (entries into the protective
field) and `field_warning_s`.

Per trial, `trials.jsonl` also keeps the drawn workers, every collision event, the robot trajectory and a digest. The
runner rebuilds one trial from its seed and checks that the digest matches.

## Analysis (`scripts/e3_analysis.py`)

```
uv run python scripts/e3_analysis.py out/e3/*/trials.csv --logs out/e3/*/trials.jsonl --out results/e3_analysis
```

- **CIs:** 95 % percentile intervals from a two-stage cluster bootstrap (2000 replicates). Each replicate resamples
  scenes, then seeds within each drawn scene. The same draw is used for every tier and policy, so cells stay paired.
- **Tests:** per tier, a paired Wilcoxon signed-rank test for each policy pair on identical (scene, seed) trials, for
  robot-moving collisions and time to goal. An unfinished trial counts at its timeout. p-values are Holm-corrected
  within each metric.
- **Outputs:**
  - `table2.md` / `table2.tex`: one row per tier x policy. Moving collisions first (and how many were from behind, how many while
    already braking), then stationary collisions (moving + stationary = all), the robot's mean / max speed at contact, success,
    frozen, min gap while moving, time within 0.5 / 1 m while moving, time stationary within 1 m, and median time to
    goal.
  - `contact_speed.md` / `.csv`, `collisions.csv` (with `--logs`): every collision event with the robot's v and w at first contact,
    the speed distribution per tier x policy (moving and stationary contacts separately, speed bins), and the checks: the
    `robot_moving` tag agrees with the logged v / w, per-trial event counts agree with `trials.csv`, and human-aware's contacts.
  - `tests.md` / `tests.csv`.
  - `scatter.svg` and `scatter_points.csv`: moving collisions against median time to goal, one point per policy x
    tier, with CIs.

## Scene selection (`scripts/e3_select_scenes.py`)

```
uv run python scripts/e3_select_scenes.py dataset/e1/<model> --n 10 --out results/e3_scene_selection
```

- **Candidates:** accepted E1 runs with physics ok, usable for E3 (a door, at least two kinds of task point, at least
  two reachable robot goals).
- **Pick:** greedy, one scene per prompt. It covers every cell-type family (engine and motor gearbox reman count as one,
  which gives 6) and every size, then new (family, size) combinations, then balances families, difficulty and size.
- **Safe during E1:** it only reads records and loads 2D grids. The trial grid itself should not run on the E1 machine
  while E1 runs.
